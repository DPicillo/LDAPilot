# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

LDAPilot is a cross-platform LDAP browser and management GUI built with the [Wails v2](https://wails.io/) framework — a Go backend with a React/TypeScript frontend compiled into a single native binary.

## Development Commands

```bash
# Live development (hot-reload frontend + auto-recompile Go backend)
# Use -s to skip frontend build (Vite serves it via hot-reload)
wails dev -s

# On Debian 13+ where only webkit2gtk-4.1 is available:
wails dev -s -tags webkit2_41

# Production build (outputs to build/bin/)
wails build
# … with version (wails.json info.productVersion), commit and build date stamped (About / diagnostics); extra args go to wails build
scripts/build.sh

# Cross-compile for Windows
wails build -platform windows/amd64

# Frontend only (from frontend/ directory)
cd frontend && npm install && npm run dev
```

Prerequisites: Go 1.26+, Node.js 22.12+ (or 20.19+), Wails CLI matching `go.mod` (`go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.0`).

Frontend stack: React 19, Vite 8, TypeScript 7 (native `tsc`), Tailwind CSS 4 via `@tailwindcss/vite` (theme lives in `src/styles/globals.css` `@theme`, there is no `tailwind.config.js`).

On Debian 13+: `sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev` (note: 4.1 not 4.0).

Tests: `go test ./...` (pure unit tests without network, e.g. `internal/ldap/binary_test.go`, `referral_test.go`, `internal/ldif/ldif_test.go`; listing timings against the large lab OpenLDAP only with `go test -tags perflab -run TestPerfLab -v ./internal/ldap`; LDIF import / export against the lab with `go test -tags ldiflab -run 'TestLDIFLab(Repro|Probe|ProbeAD|Options|Restore)' -v ./services` (own OUs, removed afterwards) and its timings with `TestLDIFPerf`, `services/ldifperf_test.go`, see `docs/ldif-import-export-notes.md`). Frontend pure-function tests (no extra dependencies, Node ≥ 22.18 type stripping): `cd frontend && node --test 'tests/*.test.ts'` (per-area files `tests/{conn,cmd,editor,tree,life,search,accounts,nav}.*.test.ts`, the fix rounds `tests/loop2.*.test.ts`, `loop3.test.ts`, `final.test.ts`, the open-points packages `opconn.test.ts`, `schema.aliases.test.ts`, the leftovers `rest.test.ts`, large directories `perf.test.ts`, next to the older per-module ones). Every module a test imports — the pure helpers in `lib/` (`ldif`, `binary`, `entryChanges`, `entryEvents`, `dn`, `menuPosition`, `password*`, `ldapFilter`, `searchFilter`, `treesearch`, `treeHitRank`, `membership`, `recycle`, `bulk`, `account*`, `uac`, `attributeGroups`, `connectionAuth`), `lib/sharedRead.ts`, `stores/accountStatusCache.ts`, `stores/bookmarkStore.ts`, `stores/tabViewState.ts` and the pure modules next to components (`components/ui/{shortcuts,objectKind,accountStatus,fit,dnParse,undo,menuTypeahead,primaryAction,hitLabel,tableSort}.ts`, `components/commands/{selectionSource,targets,accountDisplay,menuStability,panelTable,paletteSearch,addToGroups,photoPlan}.ts`, `components/connection/{profileLogic,chromeLogic}.ts`, `components/lifecycle/{newEntry,containerPickerModel,rename,events}.ts`, `components/search/{searchModel,resultsExport,snapshotModel}.ts`, `components/export/{ldifRebase,ldifRuns}.ts`, `components/bulk/moveModel.ts`, `components/editor/{ldifEdit,certificateCard}.ts`, `components/account/{newUserAccount,reportRows}.ts`, `components/recycle/descendantList.ts`, `components/schema/schemaModel.ts`, `components/browser/listColumns.ts`, `components/layout/{opTone,opLog}.ts`, `components/tree/statisticsModel.ts`) — may only import types, npm packages, or other such modules *with* the `.ts` extension (`import … from './dn.ts'`, allowed by `allowImportingTsExtensions`); Node's ESM loader does not resolve extensionless paths. Pure logic in a `.tsx` file cannot be loaded by `node --test`: put it into a `.ts` module (e.g. `ui/fit.ts` holds the toolbar / breadcrumb fit helpers that `Toolbar.tsx` / `DnBreadcrumb.tsx` re-export). `lib/membership.ts` takes `toCSV` from `lib/bulk.ts`, so `bulk.ts` must keep importing only types or `.ts` modules. AI chat tests: `node --test 'tests/ai/*.test.mjs'` (incl. `opai.test.mjs`: DN resolution, dock fit, Ask AI titles, bare @; `claudecode.test.mjs`: the Claude Code runtime settings; see Gotchas › AI UI contract tests). Opt-in check against the installed Claude Code CLI (no billed model call): `LDAPILOT_REAL_CLAUDE=1 go test ./internal/ai/mcprelay -run RealClaude -v`.

CI (`.github/workflows/ci.yml`, GitHub Actions): every push to master and every pull request runs gofmt, `go build`/`vet`/`test`, `scripts/lint-tokens.sh` (the design token lint gates G1–G12 of Gotchas › Design token rules, PCRE grep over `frontend/src`), `tsc`, both node test suites and the Vite build on ubuntu-22.04, then builds Linux (WebKitGTK 4.0 on ubuntu-22.04, `-tags webkit2_41` on ubuntu-24.04), Windows and macOS (`darwin/universal`, zipped `.app`) with `scripts/build.sh`; the Windows job runs the mutex tests (`appmutex_windows_test.go`), compiles the Inno setup (`build/windows/setup/ldapilot.iss`, Inno Setup 7.1.1 and Microsoft's WebView2 bootstrapper, both checked) and runs `scripts/windows-setup-smoke.ps1` on the runner; the job `package-linux` builds `LDAPilot-linux-amd64.deb` / `.rpm` / `.el9.rpm` / `.tar.gz` with `scripts/package-linux.sh` (nfpm 2.49.0) and install-tests them in Debian 13 and Fedora containers (see Gotchas › Installers). Builds are published **only when a release is made** (owner's rule): a pushed tag `v*` creates the GitHub release (notes = the `## [x.y.z]` section of `CHANGELOG.md`) and attaches the release files (setup, portable exe, macOS zip, Linux packages and archive; not the bare Linux binaries) plus `SHA256SUMS.txt`; never attach builds to an existing release afterwards. "Run workflow" by hand only tests and builds (run artifacts, 14 days). Builds are not code-signed / notarized.

Test lab: `cd docker && docker compose up -d --build` starts OpenLDAP (389/636), 389 Directory Server (4389/4636) and a Samba AD DC (2389/2636, GC 3268/3269, Kerberos KDC 88), each seeded with edge-case data. Credentials, profile settings per server (incl. Kerberos SPN / NTLM domain) and the lockout policies in `docker/README.md`: OpenLDAP and 389DS lock after 3 failed binds **until an admin unlocks**, the Samba domain has no lockout threshold (only `test.locked` via a PSO, 10 min), the AD Recycle Bin is off (deleted objects are tombstones). Performance lab (not started by a plain `up`): `docker compose --profile perf up -d --build openldap-perf` = OpenLDAP 2.6 on 10389/10636, `dc=perf,dc=ldapilot,dc=lab` (admin `cn=admin,…` / `admin`), 100,000 users directly below `ou=People`, 100,000 groups (40,000 directly below `ou=Groups`), generated by `docker/openldap-perf/generate.go` and bulk-loaded with slapadd; measurements and open items in `docs/perf-large-directories.md`.

Version: `services.ReleaseVersion` (`services/app_info.go`, "v0.6.0"), `wails.json` `info.productVersion` ("0.6.0": Windows file version, macOS bundle version, Windows setup and Linux packages, which need three numeric fields) and `frontend/package.json` `version` must agree (`TestReleaseVersionDeclarations`); `scripts/build.sh` stamps `v<productVersion>` (override with `VERSION=`), an unstamped build reports `<ReleaseVersion>-dev`. Release notes go into `CHANGELOG.md`.

## Architecture

### Backend (Go)

The backend follows a layered architecture:

- **`main.go`** — Wails app entry point. Creates all services and binds them to the frontend via `wails.Run()`. Embeds `frontend/dist` via `//go:embed`. Frameless window with custom title bar.
- **`services/`** — Wails-bound service layer. Each `*Service` struct has exported methods callable from the frontend JS.
  - `ConnectionService` — Profile CRUD, connect/disconnect, reconnect, ping, import/export connections (no secrets exported): `ReloadConnections` (Reload Profiles: `store.Load()`, live settings re-applied), `ImportConnections` → `ConnectionImportReport {cancelled, path, total, imported[], duplicates[], skipped[{name,reason}], needPassword[]}` (duplicate = same host+port+bind DN+base DN as a saved profile or an earlier one of the file, case/blank-insensitive: `profileIdentityKey`; `askPassword[]` lists imported ask-on-every-connect profiles, not in `needPassword`), `ExportConnections` → `ConnectionExportResult {path, count}` (`path ''` = cancelled; `ExportSelectedConnections(ids)` = the export checklist), `ConnectWithPassword(id, password, save)` (session password kept in memory until quit, or stored encrypted once the bind works); `services/auth_connection.go`: TestConnectionDetailed (server type, vendor, naming contexts, `dnsHostName`), certificate trust (GetCertificateProblem/TrustCertificate/ReplacePinnedCertificates), auth environment, `DetectServerHostName(profile)` (RootDSE `dnsHostName`, anonymous: the Kerberos SPN suggestion), `GetServerCertificates(profile)` (the chain presented over the profile's TLS mode, no bind, not verified: pin "Refresh details")
  - `BrowserService` — Tree browsing (`planNonADRoots`), AD naming contexts as tree roots + tree search bases (`treesearch_roots.go`), GetStatistics / GetStatisticsRun + CancelStatistics (+ per-category filters), GetServerInfo, `GetRootDSEAll` (`serverinfo_view.go`: `*`, `+` and the capability attributes by name, values de-duplicated, read fresh unlike the cached `ServerInfo()`), effective/direct membership (`membership_service.go`), account status + account reports + `GetReportAvailability` (`account_service.go`), deleted objects + descendant count (`recycle_service.go`), lifecycle reads (`recycle_service.go`, unlogged: `EntriesExist(profileID, dns)` → `[]EntryCheck{dn, exists, error}` (base search `1.1`, max 200 DNs), `LoginNameHolders(profileID, attr, value)` (≤ 5 DNs holding uid / sAMAccountName / userPrincipalName / mail / cn / uidNumber / gidNumber = value), `NextPosixIDs` → `{uidNumber, gidNumber, primaryGidNumber}` (highest ID in 1000…59999 + 1, else 10000), `UPNSuffixes` (AD: own domain, other forest domains, then `uPNSuffixes` of `CN=Partitions`)), `GetNewAccountPolicy(profileID, parentDN)` (`account_service.go`: New User "must change" offer), stable entry ids (`recycle_stableid.go`, unlogged: `StableIDsOf(profileID, dns)` → `[]StableIDInfo{dn, id, missing, error}` (base reads of objectGUID / nsUniqueId / entryUUID, ≤ 200 DNs), `FindByStableID(profileID, id)` → current DN or "" (equality search below the tree search bases + naming contexts; objectGUID as its 16 raw bytes)), `ListDescendants(profileID, dn, limit)` (`recycle_descendants.go`: first ≤ 200 entries below a DN, breadth first via unlogged `ChildDNs`, at most limit+1 one-level reads)
  - `EditorService` — Entry CRUD, atomic `ModifyEntry`, unicodePwd encoding, password reset (`editor_password.go`), group membership changes, account actions (unlock, enable/disable, must change, never expires, account expiration, userAccountControl), restore of deleted objects + recursive delete, certificate / PKCS #7 descriptions (`binary_service.go`), password storage policy (`password_policy.go`: GetPasswordPolicyCatalog, GetPasswordPolicy, PlanPasswordWrite, CreateEntryWithOptions, ModifyEntryWithOptions)
  - `BatchService` — Batch move dry run `BatchMovePreview(profileID, dns, target)` → `BatchMovePlan {total, ready, unchanged, failing, refused, reason, items[{dn, newDN, status move|unchanged|fail, message}]}` (target checked as BatchMove does, each entry exists, already there, name free in the target — also against another entry of the same move; pure `planBatchMove`); batch move (`BatchMove` refuses before moving anything — `refused: true`, reason in `errors[0]` — when the target does not exist / cannot be checked, is one of the entries or lies below one; entries already in the target are `unchanged`; `moved: [{dn, newDN}]`); bulk modify dry run + apply with templates (`bulk_batch.go`, `bulk_plan.go`). Deletes go through `EditorService.DeleteEntry`/`DeleteSubtree` (recycle's `DeleteEntryDialog`)
  - `SearchService` — LDAP search with paged results, filter validation; `SearchRun(profileID, runID, params)` / `CancelSearchRun(runID)` (a results tab's own search: cancelled without touching the panel's search on the same connection; `CancelSearch(profileID)` does not stop it), `ReadEntries(profileID, dns, attributes)` → `{entries, missing, errors, truncated}` (one unlogged base read per DN via `Client.ReadAttributes`, ≤ 5000, duplicates once; "Open in List")
  - `ExportService` — `Export` (preview, `limit`) + `SaveExport` (the whole export written to the chosen file in Go) + `SaveExportFile` (the Export dialog, see Gotchas › Exports), LDIF import = LDIF change files dry run + apply (`bulk_ldif.go`; adaptations `ldif_import.go`, large dry runs paged through `GetLDIFPreviewRecords`, `ldif_preview_store.go`), `SaveReportFile` (report files only), binary value save/upload, file dialogs via Wails runtime
  - `SchemaService` — Schema discovery and caching
  - `LogService` — Operation logging with Wails event streaming
  - `AuditService` — Persistent audit log on disk: `GetAuditLogRange`, live `audit:entry` events (batched, see Gotchas › Operations / audit log views), `ClearAuditLog` leaves an `AUDIT_CLEARED` record (see Gotchas › Audit details)
  - `UIService` — `SetTheme`: the resolved colour theme, persisted (`internal/config/ui_state.go`) so `main.go` opens the native window in its background colour; `GetAppInfo()` (`app_info.go`: version/commit/build date from the `main.version/commit/date` ldflags, else `ReleaseVersion + "-dev"` and `debug.ReadBuildInfo` vcs.revision/vcs.time/vcs.modified; Go, Wails, the loaded libwebkit2gtk on Linux, OS, arch, config dir); the close guard `BeforeClose` (main.go `OnBeforeClose`) + `AckClose` / `CancelClose` / `Quit` (see Gotchas › Quit guard)
  - `AIService` — thin Wails facade of the AI harness in `internal/ai` (streaming runs via `ai:*` events, approvals, encrypted chats, model discovery); `ai_backend.go` adapts the connection pool and audit log (the only AI file reading `ConnectionProfile`); `ai_delegates.go` serves the AI tools' delegates from the feature tracks (membership, account, password reset, deleted objects); `ai_claudecode_cli.go` finds the Claude Code CLI (native or in WSL, cached per settings, see Gotchas › Claude Code in WSL) and serves `GetClaudeCodeHosts` (Windows: the WSL distributions for the settings)
- **`internal/ldap/`** — Core LDAP logic using `go-ldap/ldap/v3` (aliased as `goldap`).
  - `client.go` — Connection, search (incl. controls, `SearchWithControls`), CRUD (`ModifyEntry` atomic multi-change, `DeleteEntryWithControls`), ranged attribute retrieval, referral following
  - `connect.go` — Dial/bind with timeouts, auto-reconnect (`run`/`read`/`write`), dead-connection detection
  - `auth_*.go` — Bind methods (simple, NTLM, Kerberos/GSSAPI, SASL EXTERNAL) and TLS trust (custom CA, client cert, pinning); `auth_probe.go` also has `ProbeDNSHostName` / `ProbeServerCertificates` (no bind, credentials dropped, certificate not verified, client certificate still offered, timeout ≤ 10 s); `TestProfile` fills `ConnectionTestResult.dnsHostName` after the bind, and after a failed Kerberos bind from an anonymous probe
  - `binary.go` — Binary attribute contract (classification, base64, unicodePwd encoding on write)
  - `serverinfo.go` — Cached RootDSE capabilities (`Client.ServerInfo()`, server type detection)
  - `referral.go` — LDAP referral URL parsing, credential/TLS policy and cross-server query execution
  - `pool.go` — Connection pool keyed by profile ID, `GetConnected()` for multi-directory AI, `UpdateProfile()` for live settings
  - `schema.go` — Schema attribute/objectClass discovery
  - Feature files (one prefix per feature): `treesearch_*.go` (crossRefs, child probing), `membership*.go` (membership graph + single-value edits), `password*.go` (RFC 3062, verification bind, client-side hash schemes incl. bcrypt, `password_policy.go` = per-connection password storage policy + the userPassword write hook), `recycle*.go` (deleted objects, restore, tree/recursive delete; `recycle_lifecycle.go`: `EntriesExist`, `LoginNameHolders`, `NextPosixIDs`, `UPNSuffixes`, `DNToDNSName`), `binary_cert.go`/`binary_file.go`/`binary_pkcs7.go` (certificates, PKCS #7, upload checks), `account*.go` (account status/actions/reports for AD, OpenLDAP ppolicy, 389DS; group reports in `account_groupreport.go`; the shared policy cache in `account_policycache.go`), `rootdse_all.go` (`Client.GetRootDSEAll`), `bulk.go` (existence/children checks for dry runs)
- **`internal/models/`** — Shared data types (`ConnectionProfile`, `TreeNode`, `LDAPEntry`, `SearchParams`, etc.) serialized as JSON to/from the frontend; `password_policy.go` (EffectivePasswordPolicy, PasswordWriteOptions/Plan/Report).
- **`internal/config/`** — Persistent storage:
  - `store.go` — Connection profiles (JSON + encrypted passwords)
  - `crypto.go` — AES-256-GCM encryption for passwords and API keys
  - `ai_config.go` — AI config v2 (engine, provider/flavor/URL, encrypted API key, model, per-connection access levels bound to provider hosts, write switch, redaction list, per-connection notes, Claude Code settings incl. `runtime` "" / windows / wsl, `wslDistro`, `wslPath`)
  - `chat_store.go` — AI chat directory (`Dir()`); the chats themselves live in the encrypted store `internal/ai/chatstore`
  - `audit.go` — Audit log entries
  - `paths.go` — Config directory resolution (`~/.config/LDAPilot/`)
- **`internal/ldif/`** — LDIF and CSV import/export logic; `changes.go` parses RFC 2849 change records (`ParseChanges`).

### Frontend-Backend Contract

Go service methods are exposed to JavaScript via Wails bindings. The frontend accesses them through `frontend/src/lib/wails.ts` which dynamically reads `window.go.services.<ServiceName>`. TypeScript types in `types/ldap.ts` (and the feature files in `types/`) must stay in sync with Go structs in `internal/models/`. Feature bindings live in `lib/wails-<feature>.ts` and use `getBinding` from `wails.ts`; after adding or changing an exported service method run `wails generate module`.

## Gotchas

Bullets are grouped by area. The five rules bullets after "No linter/formatter configured" (sweep review, UX loop rounds 2 and 3, UX final round, design tokens) record cross-cutting UI decisions of the v0.5 design and UX walkthrough; they refine the area bullets above, so when a behaviour changes, update both places.

- **Password/API key encryption**: Both connection passwords and AI API keys are encrypted at rest via AES-256-GCM (`internal/config/crypto.go`). Never store plaintext secrets.
- **Auth & TLS trust** (`internal/ldap/auth_*.go`): every bind (main connection, temporary paging connections, referrals) goes through `bindConnHost` (exception: `CheckBind` dials an anonymous copy of the profile and binds as the entry itself). NTLM: Samba only offers SASL `NTLM`, so `dialServerNTLM` reads the RootDSE and binds with raw NTLMSSP before handing the socket to go-ldap; other servers (real AD) get go-ldap's Sicily `NTLMBind`. Kerberos: gokrb5 with password or credential cache (`FILE:` only; default resolved like MIT in `auth_ccache.go`: profile → `KRB5CCNAME` → krb5.conf `default_ccache_name` incl. include/includedir → `/tmp/krb5cc_<uid>`, macOS `API:`), realm always uppercased, SSPI for the logged-on user on Windows (`auth_sspi_windows.go`, build-tagged); a KDC override builds the krb5 config in code (TCP only), else krb5.conf + DNS SRV; SPN defaults to `ldap/<host>` (override needed when dialing an IP/alias). No SASL security layer is negotiated, so DCs requiring LDAP signing need LDAPS/StartTLS. NTLM/Kerberos user and password reuse `BindDN`/`Password` (encrypted at rest); `SaveConnection` drops the password for methods that do not use one. TLS verification is done in `VerifyConnection` (Go's own check is off): system roots + profile CA certs; a pinned SHA-256 leaf fingerprint is accepted even if chain, host name or validity fail. Failures are `*ldap.CertificateError` (message prefix `untrusted TLS certificate`); after a failed Connect/Reconnect `ConnectionService.GetCertificateProblem` returns the chain and the frontend opens `CertificateTrustPrompt`. Connection dialog: the CA certificate file is checked automatically when its path changes (450 ms debounce) and when the dialog opens ("Check again" re-reads it); pasted PEM text is described per certificate after a debounce, text without a PEM block shows the parser error on the field (DEF-03). Kerberos with a host that is an IP / alias (`needsExplicitSPN`): the dialog reads the RootDSE `dnsHostName` (debounced, or "Look up the server's name") and offers "Use ldap/<name>"; a failed Kerberos bind in Test Connection offers "Use SPN ldap/<name>" too (`spnSuggestion`, DEF-05).
- **Connect/Reconnect concurrency**: `Pool.Connect` dials without the pool lock; overlapping calls for one profile all return the result of the *newest* call. A Connect overtaken by `Disconnect`/`DisconnectAll` returns `ldap.ErrConnectCancelled` ("…connection attempt cancelled", unwraps to `ErrNotConnected`); the frontend ignores it (`wails.isConnectCancelled`).
- **connections.json changed outside LDAPilot** (`internal/config/store.go`): every write compares the file's SHA-256 with what the store last read/wrote; a changed file is re-read and the write applied on top (external edits are never overwritten); a write that conflicts (the same profile edited or deleted there) or an unreadable file is refused with `config.ErrExternalChange` ("connections.json changed outside LDAPilot …, repeat your change"). The store calls the external-change handler → `connections:changed` event → `connectionStore.loadProfiles()` + info toast. Reload Profiles = `ReloadConnections`.
- **Password prompt on connect**: Connect/Reconnect of a profile that needs a password none is stored for fails with `ErrPasswordRequired` ("password required: …") before dialing; `connectionStore.connect/reconnect` catch `isPasswordRequired`, open ConnectPasswordPrompt (mounted in AppLayout's overlay hosts) and call `ConnectWithPassword` (optional "Save password"); a rejected password asks again with the server's message; Cancel rejects like a cancelled connect (callers ignore it). `useConnectionWatch` treats "password required" and a cancelled prompt as a credential stop (no automatic retries). Imported profiles never contain passwords; `needPassword` in the import report lists them. **Ask for the password on every connect** (`ConnectionProfile.askPassword`, DEF-07): only for methods that send a password (simple with a DN, NTLM, Kerberos with user/password; Go `dropUnusedPassword` clears it otherwise). Such a profile never stores a password (`SaveConnection`, `dropUnusedPassword`; the store ignores and never writes one — not even a sealed one —, `importProfile` drops a legacy plaintext one); `Connect`/`Reconnect` fail with a `passwordAskedError` (unwraps to `ErrPasswordRequired`, text "password required: this connection asks for the password on every connect (<name>)"); `ConnectWithPassword` uses the typed password for that connect only (no session password, `save` ignored); the open client keeps it in memory for its own re-dials (ping auto-reconnect) until disconnected. ConnectPasswordPrompt hides "Save password" for it; purpose 'test' (`requestConnectPassword(p, err, 'test')`) is Test Connection of a saved profile without a stored password (`testSavedConnection`; a connected non-ask profile tests with its session password). The dialog's password field is then "Password (not saved)": Test uses it, Create and Connect primes it once (`primeConnectPassword`), Save drops it (`profileForSave`). Exports carry `askPassword`; the import report lists such profiles in `askPassword` (not `needPassword`).
- **Bind error hints**: `ldap.BindErrorHint(err)` (`internal/ldap/errors.go`) maps the AD/Samba `data <code>` sub-status (525, 52e, 530, 531, 532, 533, 568, 701, 773, 775) to a sentence appended to connect and test errors ("… — wrong password or user name (AD code 52e)"). Failed connects are logged as `CONNECT` errors in the profile's operation log; the pool keeps one logger per profile across clients (`Pool.Logger(id)`), `ConnectionService.Connect` attaches the `operation:log` stream before dialing. A failed connect toast has "Edit…" (`setConnectionEditor`, set by `registerConnectionCommands`).
- **Profile limits**: page size 1–5000, timeout 1–600 s — validated in the dialog (`PROFILE_LIMITS`, `validateConnectionForm`) and clamped in Go (`clampProfileSettings` on save/import, `connect.go` for the dial timeout).
- **Pinned certificate changed**: `GetCertificateProblem` / test results set `pinnedChanged` + `previousPins` (with `pinnedAt` from `ConnectionProfile.tlsPinnedAt`, stamped by `normalizeAuthSettings` for new pins). CertificateTrustPrompt then shows "Server certificate changed", old vs new SHA-256, no one-click trust button: **Trust New Certificate and Connect** stays disabled until "I verified the new certificate" is ticked; "Remove the old pin" (default on) uses `ReplacePinnedCertificates`. **Pin details** (DEF-04): `ConnectionProfile.tlsPinnedInfo` (fingerprint → `PinnedCertificateInfo {subject, issuer, notBefore, notAfter}`), recorded by `TrustCertificate`/`ReplacePinnedCertificates` from the trust prompt's chain and by the dialog's "Trust this certificate"; `normalizeAuthSettings` → `prunePinInfo` keeps entries only for remaining pins (canonical keys, texts ≤ 1 KiB); exported/imported. TLSTrustSettings shows "CN · issued by … · expires …" (expired badge) or "Certificate details not known (manual or older pin)" with "Refresh details from the server" (`GetServerCertificates`, `pinInfoFromChain`). The "Server certificate changed" prompt shows the old pin's details (`PinnedCertificate.subject/issuer/notAfter`).
- **Active profile and saved-profile lists**: `connectionStore` remembers the active profile in localStorage `ldapilot-active-profile` (try/catch); `useConnectionWatch` → `ensureActiveProfile()` activates, when connections are open but none is active (page reload, active one disconnected), the active editor tab's profile, else the last active one, else the first connected (`profileToActivate`). The welcome screen, the Explorer and the Connections panel preselect / tab-stop the **last used** profile (`shellState.lastUsedProfileId`), never the alphabetically first; type-ahead keeps a blank inside a burst (`typeAheadKey`); Space outside a burst still selects the row. Connections list multi-selection (DEF-02, `aria-multiselectable`): Ctrl+Click / Ctrl+Space toggle, Shift+Click / Shift+Arrow range (from the anchor while the focused row is selected, else from the focused row), Ctrl+A, Escape back to the active row; plain click / Space = one row + active as before. Del, the row menu ("n connections": Export n…, Clear Selection, Delete n…) and the selection bar act on the selection; `DeleteProfilesDialog` lists the names (≤ 8, "… and n more"), `connectionStore.deleteProfiles` (one toast), focus → `focusAfterRemovals`. Export Connections… (every entry point) opens `ExportConnectionsDialog` with several profiles (all checked, or the list's multi-selection), one profile goes straight to the save dialog (DEF-06).
- **Shell view after a reload**: `uiStore` restores the side bar activity and the bottom panel (visible + tab) from localStorage `ldapilot-shell-view` (`chromeLogic.parseShellView`, written by a store subscription; AI is not restored while docked right). Because the side bar may now open on another panel than Connections, the saved profiles are loaded once at start-up by `ensureProfilesLoaded()` (StatusBar and ConnectionManager), not by the Connections panel alone. Logo: `frontend/src/assets/logo.png` is a 512 px transparent PNG in a mid blue (#2f7cda, ≥ 3.5:1 on the dark and the light surfaces), used on the welcome screen, About and the title bar in both themes (DEF-01); the native icons are the same mark in that blue on a white rounded-square plate with a light hairline edge (readable on light and dark taskbars / docks): `build/appicon.png` 1024 px (macOS grid, 824 px plate), `build/linux/icon.png` 256 px (the Linux window icon, embedded by `main.go` as `linux.Options.Icon` with `WebviewGpuPolicyNever` kept; GDK drops icons larger than one X request, so never the 1024 px one), `build/windows/icon.ico` 16/24/32/48/64/128/256 (plate full bleed and strokes thickened at ≤ 48 px); macOS's `iconfile.icns` is generated from `appicon.png` by `wails build`.
- **Quit guard**: every close (title bar ×, File ▸ Exit, Alt+F4, window manager; Wails' `runtime.Quit` also runs `OnBeforeClose`) → `UIService.BeforeClose` holds it and emits `app:before-close` → `useQuitGuard` answers `AckClose` and quits (`QuitApp` = `UIService.Quit`, which allows the next close) unless an open batch dialog (`bulkDialogStore.batch`), LDIF import dialog (`importLDIF`), a running recursive delete (`recycle:delete-progress` without phase "done"; `DeleteSubtree` also sends "done" when listing the subtree fails; a run silent for 120 s counts as ended) or tabs with unsaved edits (`tab.dirty || hasUnsavedEdits`) → ConfirmDialog "Quit anyway?" (Keep Working → `CancelClose`). Fail-safes in Go: no AckClose within 2 s, or a second close request within 5 s, closes anyway. File ▸ Exit runs `requestQuit`.
- **Status bar**: connection switcher (rows switch / connect; connecting from it shows the Explorer and focuses the tree; submenus Disconnect ▸ / Edit Connection ▸ / Test Connection ▸ per profile; an active profile that is not connected reads "<profile> – not connected · n open"), host:port and base DN are copy buttons (empty base DN: "all naming contexts"), selection summary "n children of <name> · m selected", the security chip and the password-storage chip are buttons with a tooltip that open Edit Connection at TLS trust / Password storage. File menu and palette: `connection.edit` "Edit Connection "<name>"…", `connection.test` "Test Connection" for the active profile; Help ▸ Report Issue opens a prefilled `/issues/new?body=` (version, OS, active server type); About ▸ Copy diagnostics copies the same text, never hosts/DNs/credentials.
- **Referral following**: `internal/ldap/referral.go` handles LDAP referral chasing. BER class constants: `ClassContext=128`, `TypeConstructed=32` (not 2/1). Referrals are extracted from the error packet, not the result. Profile credentials are only sent to the profile's own server (same host *and* port) or to hosts in a trusted domain (incl. subdomains) on a standard LDAP port (389/636/3268/3269) or the profile port. Trusted domains come only from the trailing `DC=` components of the profile base DN and of the server's `defaultNamingContext` (RootDSE); domains on the public suffix list (`golang.org/x/net/publicsuffix`: `com`, `co.uk`, `ngrok.io`, …) are never trusted, and the host name's parent domain is deliberately not used (shared zones like `cloudapp.azure.com`). Other servers get an anonymous bind. A profile using TLS never follows a referral in plaintext (`ldap://` is upgraded with StartTLS). Each follow writes a `REFERRAL` log entry with the decision. A referral URL without DN means "same DN as the request" (RFC 4511).
- **Read-only is enforced in `internal/ldap`**: every client write returns `ldap.ErrReadOnly` on read-only profiles; code that sends its own modifying requests must call `Client.CheckWritable()` first. `ConnectionService.SaveConnection` calls `Pool.UpdateProfile`, so read-only, page size, timeout, referrals, name and base DN apply to a live connection immediately; host/port/TLS/bind changes need a reconnect. Batch operations and LDIF import are refused on read-only connections and are audited like `EditorService` (`writeAudit`, password values masked).
- **Audit masking**: `services/audit_helper.go` masks values of attributes in `sensitiveAttributes` and of names containing `password`/`pwdhistory`/`secret` or ending in `pwd`/`rootpw` (LAPS, cn=config root passwords, BitLocker keys, …); `pwdLastSet`/`pwdReset` stay visible.
- **Audit details** (`services/audit_helper.go`): MODIFY / DEL_ATTR details carry the values before the write (`auditBefore` reads the replaced / removed attributes with `Client.ReadAttributes` — unlogged — before the write, `auditBeforeFromEntry` uses the entry a bulk run read anyway; `describeChangesWithBefore`: "replace description: [old] → [new]; add mail: +[x]; delete phone: [1] → (removed)"; secrets are never read and stay masked, binary values by size). Used by `EditorService.ModifyAttribute/AddAttribute/DeleteAttribute`, `ModifyEntryWithOptions` (Edit Entry, password-aware inline edits), `BatchApply`, LDIF modify records (account actions and membership changes name their values without it). - **Binary attribute contract**: `LDAPAttribute.Binary` / `AttributeChange.Binary` = every value is standard base64 (RFC 4648, padded) of the raw bytes — in both directions. `convertEntry` marks an attribute binary if its name is in `knownBinaryAttributes` (`binary.go`), it has the `;binary` option, or any value is invalid UTF-8 / has control chars other than tab/CR/LF. Every write path (`AddEntry`, `ModifyEntry` + wrappers, batch, LDIF import) base64-decodes binary values (`rawValues`). LDIF export writes binary values as `attr:: <value>` unchanged, CSV carries base64, the AI tools show `<binary N bytes, mime>`. Frontend: never put a binary value into a text field and send it back as text (AttributeTable/EditEntryDialog hide text editing for binary attributes).
- **unicodePwd**: values in `AddEntry`/`ModifyEntry` are plain-text passwords and get encoded (`"pw"` as UTF-16LE) for add, delete and replace; `replace` = admin reset, `delete old` + `add new` in one `ModifyEntry` = the user's own change.
